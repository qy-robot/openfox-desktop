# 技能市场与设备目录 UI

这两个入口是 RoboCoding Desktop 的独立产品模块。技能市场用于查看公开介绍并管理本机已添加技能；设备目录用于选择机器人型号、开发方式，并查看公开配置和教程。它们不属于插件市场，也不共享插件安装流程。

## 视觉方向

参考界面的有效特征是：顶部将搜索和“已添加”作为高频操作；分类横向排列；内容区使用疏朗的多列图标条目，而不是密集的大卡片；详情在带遮罩的居中弹窗中完成，关闭后回到原来的浏览位置。

Desktop 沿用现有系统字体和主题变量。主画布保持安静，图标圆环使用蓝、紫、青、橙四种低饱和强调色来帮助扫视分类。技能条目只保留图标、名称、单行介绍、适用范围和添加按钮。窗口变窄时从四列依次收缩为三列、两列和单列。

设备目录保持“型号 → 开发方式 → 配置与教程”的流程。设备卡片用于型号比较，已选型号有清楚的左侧强调线；详情区展示当前开发方式对应的公开说明、配置和受限飞书教程，不推断设备能力或连接状态。

## 公开数据边界

客户端只接受技能的 `overview`、`inputs`、`outputs`、`limitations` 与基本目录元数据。技能正文、提示词、内部工作流和执行步骤不属于公开契约，Desktop Host 会在响应投影时丢弃意外字段，客户端解析器也不会保留或检索这些字段。

技能列表不得展示虚构使用人数、评分、资料量或执行成功声明。未开放执行的发布技能只显示“仅介绍”；本地示例必须明确其演示边界。目录失败、保存失败和空目录都提供可操作的重试或清除筛选入口。

## 目录接口

- 技能市场通过 Desktop Host 的技能目录代理读取组合目录；这保留技能目标与设备型号的交叉校验。
- 设备目录通过独立的设备目录代理读取 `robots`，不依赖技能目录成功。
- 本地示例服务继续兼容原组合目录；正式服务分别使用 `/api/catalog/devices`，组合 `/api/catalog` 作为技能市场兼容入口。
